# 構成

- `index.html`: 既存エディターのHTML/CSS/JavaScriptソース。会議用ライブラリと編集処理の挿入マーカーを含む。
- 会議・背景管理・画像取込・ページ移動・手のひら・自動復旧の処理は `index.html` に含める。基本操作はビルド時のコード挿入に依存しない。PDF/PPTXライブラリだけをビルド時に同梱する。
- `src/meeting-tools.mjs`: PDF背景処理の公開API、html2canvasによるページ合成、jsPDFとPptxGenJSによる書き出し。配布版ではMeetingToolsとして利用。
- `src/pdf-background.mjs`: PDF.jsの取込と再描画、1文書の解析キャッシュ、キャンセル可能な直列描画キュー。
- `src/pdf-render-plan.mjs`: ページの配置・表示領域・倍率から描画範囲と解像度を計算。最大8192px/辺・約840万画素に制限。
- `scripts/build.mjs`: esbuildでライブラリとPDF標準フォント/CMap/画像デコーダをまとめ、単独ファイルの`dist/index.html`を生成。第三者ライセンス表示も生成。
- `tests/fixtures/v0.6.html`: SHA256で照合する旧原本。
- `tests/e2e`: Chromiumで既存編集操作と会議資料の入出力を検証。サーバーはdistを提供し、file://起動も検証する。
- `.github/workflows/ci.yml`: 基本テスト、Chromium E2E、旧原本の不具合再現。テスト結果と配布版をartifactとして保持。
- `.github/workflows/pages.yml`: mainからビルドしたdistを公開。

## ビルドと配布

`npm ci && npm run build`。dist/index.htmlをブラウザで開く。実行時にCDNへ接続しない。PDF workerは同梱コードからclassic Blob Workerとして起動し、解析を画面操作とは別スレッドで行う。単独HTMLのfile://でも起動できるよう、Workerの準備完了を待ってPDF.jsへ接続し、文書を閉じる際に停止する。Workerを起動できない環境では同梱コードによるメインスレッド処理へフォールバックする。PDFの解析・画像化は端末内で行い、大きな資料では処理に時間がかかる。

## 保存形式

JSON version:1、width/height、screens/elementsの構造は維持する。背景は画面ごとの任意フィールド`background`へ、PNGのdata URL、配置、透明度、表示/ロック、名前を保存する。背景をelementsへ混ぜないため、部品の前後操作で背景が上へ出ない。旧JSONに背景フィールドは不要。

PDFの元バイト列はプロジェクトの任意フィールド `pdfSources` に文書ごとに1つのBase64文字列として保持する。各背景の任意フィールド `pdf` は `sourceId/pageNumber/pageWidth/pageHeight` を保存する。プレビューPNGは取込時に最大144dpi相当・長辺約2400pxで作成し、旧形式の背景とも互換性を維持する。JSON・自動復元に元PDFを含める。未参照ソースは削除し、Undo用スナップショットには削除前データを残す。

編集画面では元PDFから表示領域と周囲192画面pxをキャンバスへ再描画する。先読みで表示領域の解像度が下がる場合は表示領域だけを描画する。`pdf-preview-cache.mjs` のキャッシュは最大2タイル・合計8,388,608画素で、操作中も既存タイルを残し、範囲と画素密度が足りる場合は再描画を省く。新規要求は180ms集約し、進行中の描画が新しい表示範囲を満たす場合は継続する。古い要求は取り消し、完了した最新の結果だけを表示する。解析済みページは最大2ページ保持し、描画途中はUIへ処理を譲る。描画タイルは保存データに入れない。部分タイルの範囲だけPNGをマスクし、タイル外にはPNGを残す。透明度は重複合成せず、背景移動の入力は従来の画像要素で受け取る。元PDFがない旧データや未ビルドHTMLはPNGプレビューを表示する。保存済みの元PDFから描画できない場合もプレビューを残す。

## 出力

HTMLは背景と既存の要素を同梱したページ切替プレビュー。PNG/PPTXは全画面を画像として合成する。PDFは `pdf-vector-core.mjs` で元PDFページをForm XObjectとして保持し、通常の文字・線・図形をベクターで重ねる。`pdf-vector-export.mjs` はDOMから文字位置とSVGパスを取得し、複雑なUI部品のみ部品単位の透過PNGにする。元PDFのCropBoxと90度単位の回転、透明グループ、ページ内のクリップを処理する。日本語フォントは同梱TrueType（gzip）を展開し、使用した字形だけを文書共通のサブセットとして埋め込む。同一画像データはPDF文書単位のキャッシュで共有する。`pdf-fontkit.mjs` は固定依存fontkit 1.1.1の短いlocaテーブルで奇数長の字形が破損する問題を避けるため、TrueTypeサブセットの各glyfレコードを偶数バイト境界へ整列する。CFF/WOFFのサブセットは互換性検証で文字欠落を認めたため採用しない。注釈・フォーム等、追加CSS、未収録文字は出力前に検査する。A4/A3は規定mmサイズを使い、その他は96px/inで換算する。PPTXは1画面1スライドの画像であり、内部要素を個別編集する出力ではない。

HTML部品と外部URL画像を含むPDF/PPTX出力はエラーで中止する。追加CSSやフォント差など、ブラウザ上のすべての表現を完全に再現することは保証しない。

## 復旧と失敗処理

IndexedDBへ800msの遅延で自動復旧データを保存する。前回データの復旧/破棄を選択する前に上書きしない。容量不足などの保存エラーをUIに表示する。Undo/Redo履歴は32Mi文字を目安に制限し、少なくとも直前1件を残す。

資料取込は全ページの変換が成功した後に状態へ反映する。取込・出力中は編集操作を停止する。JSON保存ボタンによるダウンロードの開始と、利用者の保存先への書込み完了は別であり、後者はブラウザの権限外。


## 仮配置とページ寸法

作図中の点・固定位置・中央配置の基準点は `drawing` にのみ保持し、Enter確定時に1回のスナップショットで保存モデルへ追加する。Backspaceは固定位置、作図点、中央配置の基準点の順に一段戻り、作図外ではUndoを行う。文字編集・IME・モーダル中は作図キーを適用しない。

任意フィールド `screen.canvasWidth/canvasHeight` はページ固有の編集寸法、`text.textFit` は文字枠の自動調整、`box.corners` は4つの角の正規化座標を保持する。旧ファイルは従来の幅・高さと矩形を利用する。`page-geometry.mjs` は出力範囲を背景全体へ揃え、PDFは元の物理ページ寸法を使う。ベクター合成はページごとに座標変換とクリップを設定する。PPTXは共通スライド寸法のため縦横比を保って配置する。

ZIPはJSZipを単独HTMLに同梱し、ノートJSONとプロパティ設定をまとめる。ZIP復元はノートと設定を検証してから反映し、外部ファイルの展開・実行はしない。手動保存先のFileSystemHandleは実行中のメモリにのみ保持する。
